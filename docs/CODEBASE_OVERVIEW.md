# Codebase Overview

_Generated by the learn-codebase skill on 2026-08-28 at commit `c713346`._

## Summary

QuickLogin 是一个 Chrome MV3 扩展（v3.4.0），解决「在同一浏览器窗口内，对内部低代码平台
（`tonbridge-config.aksoegmp.com`，无状态 JWT Bearer 鉴权）并行在线多个账号」的问题。
每个账号一个独立标签页，页面呈现层完全隔离，账号切换/管理通过并行管理页与「账号轮盘」进行；
账号密码以 AES-GCM 加密存于本地 IndexedDB。它替代了旧的 MV2 SessionBox 还原版（依赖
webRequestBlocking/proxy/Firebase，靠 Cookie 单点隔离，对 Bearer 鉴权无效），并先后淘汰了
「免密快速切换」（v2.1 串行）与「本地引擎 CDP 多开」（v2.2，已废弃但代码仍在仓库内）两条路线。

## Tech stack

- **Languages:** TypeScript 5.6（strict），少量 Node 脚本（mjs / ps1）
- **Runtime:** Chrome / Edge MV3 extension；Node 20+（构建与工具脚本）
- **Build / package manager:** npm workspaces（`packages/*`）+ esbuild 0.24（`scripts/build.mjs`）
- **Datastores:** 扩展侧 IndexedDB（账号/会话）、`chrome.storage.session`（运行时状态）、
  `chrome.storage.local`（配置/封锁名单/加密种子）；废弃引擎侧 SQLite（better-sqlite3）
- **Testing:** Playwright（playwright-core）E2E 取证台架 `tools/e2e/harness.mjs`
- **Skills applied:** learn-codebase

## Architecture

纯浏览器四平面隔离网络栈（`docs/PROJECT-STATUS.md` §2 与 `packages/extension/src/background/core/tab-rules.ts` 为准）：

```
┌─ MV3 扩展 ────────────────────────────────────────────────────────────┐
│ service-worker.ts（消息路由/轮盘/角标诊断）                              │
│  ├─ core/parallel-session.ts   绑定表 tabId↔accountId、token 捕获、编排  │
│  ├─ core/tab-rules.ts          每绑定 tab ≤3 条 DNR session 规则        │
│  │    AUTH: Authorization→Bearer <token>（xhr/ws/sub_frame）           │
│  │    COOKIE: 出站 Cookie 全量剥离（全类型）                             │
│  │    CACHE: GET XHR 追加 _qlck=t<tabId> 分区 HTTP 缓存（redirect 规则）│
│  ├─ core/parallel-store.ts     账号 CRUD（IndexedDB v2 accounts）      │
│  ├─ core/credentials.ts        AES-GCM 凭证加密（PBKDF2 种子）           │
│  └─ 遗留：navigation/session-manager/account-registry（v2.1 免密切换） │
│ content/                                                            │
│  ├─ shield-main.ts   MAIN world 壳：localStorage 命名空间化、           │
│  │                   document.cookie 虚拟 Cookie 袋、种子直灌、嗅探上报  │
│  ├─ shield-bridge.ts ISOLATED 桥：postMessage ↔ chrome.runtime 中继     │
│  ├─ auto-login.ts    登录表单自动填表（顶层直填 srcdoc iframe 密码框）   │
│  ├─ title-hook.ts    标签标题持续维持                                   │
│  └─ wheel-overlay.ts 页面内 Shadow DOM 轮盘浮层                         │
│ ui/                                                                  │
│  ├─ parallel/   并行管理主页（站点授权、账号增删、状态徽标、3s 轮询）    │
│  ├─ wheel/      轮盘小窗（受限页兜底形态）                              │
│  └─ popup/      轻量启动器（打开并行页 / 授权当前站点）                  │
└───────────────────────────────────────────────────────────────────────┘
packages/engine/  废弃：NM host + CDP spawn 每账号独立 Chrome 实例 + SQLite（无扩展侧调用方）
packages/shared/  nm-protocol.ts（仅被废弃引擎与孤儿 nm-client.ts 引用）
tools/e2e/        Playwright 取证台架（SW 日志 / DNR 规则 / 身份解码 / 线上头嗅探）
probe/            诊断脚本 probe1–8（gitignored，未入库）
```

## Key modules

| Path | Responsibility |
| --- | --- |
| `packages/extension/src/background/service-worker.ts` | 消息分发（`par.*`、`wheel.toggle`、`session.*`）、轮盘三级降级链、快捷键命令、角标闪标诊断 |
| `packages/extension/src/background/core/tab-rules.ts` | 三条 DNR session 规则的构建/装载/换 token/冷启恢复/孤儿清理；`CACHE_PARTITION_ENABLED` 回退开关 |
| `packages/extension/src/background/core/parallel-session.ts` | tabId↔accountId 绑定表、token 双通道捕获（storageWrite 上报 + Authorization 嗅探）、种子推送、导航重推、授权健康门控（`enforcementOff`） |
| `packages/extension/src/content/shield-main.ts` | MAIN world：`Storage.prototype` 方法级补丁把绑定标签页 localStorage 重定向到 `__ql_ns_<accountId>__`；`document.cookie` 虚拟化为命名空间内 Cookie 袋；bind 种子静默直灌；晚到 bind 走 sessionStorage 守卫 reload 一次 |
| `packages/extension/src/content/shield-bridge.ts` | ISOLATED↔MAIN↔background 双向消息中继 |
| `packages/extension/src/content/auto-login.ts` | 自动登录：顶层 frame 直填同源 srcdoc iframe 密码框（React 受控组件用原生 setter + input/change 事件） |
| `packages/extension/src/ui/parallel/parallel.ts` | 并行管理主页：站点授权清单、账号增删开、实时徽标（在线/待登录/未授权·已暂停）、3s 轮询 |
| `packages/extension/src/ui/wheel/wheel.ts` + `src/content/wheel-overlay.ts` | 账号轮盘双形态：普通页 Shadow DOM 浮层优先，受限页独立小窗，最终降级标签页 |
| `tools/e2e/harness.mjs` | E2E 取证台架（交互式 / `QL_E2E_SELFTEST=1` 冒烟） |
| `packages/engine/*`（废弃） | 旧本地引擎：NM host 主循环、CDP 直连自动登录、每账号独立 profile spawn 多开、SQLite 账号库 |

## Data & control flow

**打开账号（`par.open`）**：`parallelSession.open(accountId)` → 若无既有绑定标签则
`chrome.tabs.create({url: https://host/ 或 /login})` → 写绑定表（内存 + `chrome.storage.session`）
→ 下发待自动登录凭证（按 tabId 缓存，60s TTL）→ `pushBind`（bind 种子 = token/身份/指纹快照）
→ 标题改写 → `syncAccountRules` 装 COOKIE/CACHE 规则（AUTH 规则待有 token 才装）。

**登录后 token 捕获**：站点把 JWT 写进 `localStorage.__auth_token__` → MAIN 壳 `setItem` 补丁
→ `reportStorageWrite` → postMessage → ISOLATED 桥 → background `handleBridge` → JWT 形态校验
→ 存 `chrome.storage.session` → 该账号全部绑定标签页装载/更换 AUTH DNR 规则。二级通道：
fetch/XHR 出站 Authorization 头嗅探。登出（token 键置 null）反向摘规则。

**SW 冷启恢复**：`parallelSession.restore()` 读 session 存储重建绑定表与 token 快照 →
`tabRules.restore()` 与浏览器现存 session 规则做差集（孤儿清理 + 缺失重建）→ 按授权健康门控重装。

**免密切换遗留路径**（v2.1，UI 已移除但后台仍完整接线）：`session.open` →
`navigation.switchAccount` → 清 Cookie + localStorage → 导航 `/login` → 自动填表 → 标题改写。

## Entry points

- 扩展入口：`packages/extension/manifest.json`（MV3；background SW + 4 个 document_start/idle
  内容脚本 + `quick-wheel` 命令 + `optional_host_permissions: ["*://*/*"]`）。
- 后台入口：`packages/extension/src/background/service-worker.ts`（装载 navigation/parallel
  监听器；`restore()` 冷启自举）。
- 构建入口：`scripts/build.mjs`（`node scripts/build.mjs [--watch]` → `dist/` + `packages/engine/dist/`）。
- 测试入口：`tools/e2e/harness.mjs`。

`--load-extension`，台架强制使用 Playwright 自带 Chromium。

## Conventions

- 版本号三处必须一致：根 `package.json`、`packages/extension/manifest.json`、
  `src/shared/constants.ts` 的 `EXT_VERSION`（当前均为 3.4.0，一致）。
- 消息协议集中定义：`src/shared/messages.ts`、`constants.ts`（storage 键 / postMessage 通道 / 配色）。
- 存储键带前缀区分新旧代际：`sb:`（v2.1 遗留）、`ql:`（并行模式）。
- 每条 DNR 规则显式写全 `resourceTypes`（防静默漏掉资源类型）；session 规则 id 按平面分段
  （AUTH 1xxxxx / COOKIE 2xxxxx / CACHE 3xxxxx）。
- 后台向内容脚本推送一律「尽力而为 + 事件重推」：`pushDown` 失败不报错，靠 `hello` 握手重试
  与 `tabs.onUpdated(loading)` 重推收敛。
- 错误处理：后台对外统一 `{ok, data|error}` Result 包装；内容脚本副作用全部 try/catch 忽略。

## Risks & rough edges

**功能层面（开放问题）**

1. **四象限身份泄漏未定位**（最高优先级，`docs/PROJECT-STATUS.md` §5.1、CHANGELOG 3.4）：
   三标签（管理员 A/B + 普通用户 U）实测「身份跟随第一个登录者/首开顺序」，存储/ Cookie/ HTTP
   缓存三平面已排除，头号候选是站点自身 Service Worker / Cache Storage 自建缓存，或服务端按
   设备指纹（`__device_fp__`）合并会话。诊断脚本已内置 CHANGELOG §3.4，E2E 台架目标是把取证自动化。
2. 站点自己写入 IndexedDB / CacheStorage 的键完全逃逸四平面（RESEARCH §6 风险 1，未实现虚拟化）。
3. 站点 SW / sharedWorker 内部发起的 WebSocket 升级请求不受 DNR 规则控制（Chromium bug 1285664，
   RESEARCH §6，未做 `new WebSocket()` URL 改参兜底）。
4. token 刷新流未经实测（RESEARCH §10 待办）；多 tab 同账号刷新风暴只有文档预案（Web Locks 双检），
   无代码。
5. main_frame 导航刻意不改写 Authorization（保护静态资源/SSO 语义）——若存在身份敏感的顶层导航
   请求，会漏。
6. 轮盘浮层在未授权站点降级为独立小窗：用户已知悉接受（PROJECT-STATUS §5.2，非故障）。

**当前 checkout 工具链状态（2026-08-28 实测）**

7. `npm run typecheck` 失败：`TS2688: Cannot find type definition file for 'node'`。
   根 `node_modules` 只装了 esbuild/typescript（`@types` 为空；缺 @types/node、@types/chrome、
   playwright-core、better-sqlite3、@primno/dpapi、chrome-remote-interface）。需要完整
   `npm install`（注意 better-sqlite3 为原生模块，Windows 需编译工具链）。
8. `npm run e2e` 必然失败：`tools/e2e/harness.mjs` 第 29–30 与 54–55 行重复声明
   `const SITE_HOST_DEFAULT` / `const PERM_URL_HINTS` → SyntaxError（已用 `node --check` 验证）。
   即便修复，根 `node_modules` 无 playwright-core，import 也会失败。
9. `dist/` 已过期（本次分析前为 2026-08-26 的 v2.2–2.4 时代产物，含已删除的 `ui/options/`，
   缺 shield/parallel/wheel 产物）——「装载即测」仅对新鲜构建成立。分析过程中已重跑
   `npm run build` 重新生成（dist/ 在 .gitignore 内，不入库）。

**代码与文档卫生**

10. 废弃代码未清理：`packages/engine/`（v0.1.0，NM host + CDP 多开 + SQLite）仍被
    `tsconfig.json` 纳入 typecheck、仍被 `scripts/build.mjs` 打包（产出 `packages/engine/dist/engine.cjs`），
    但扩展无 `nativeMessaging` 权限、无任何调用方；`packages/extension/src/background/nm-client.ts`
    为孤儿文件；`service-worker.ts` 的 `session.*`（list/update/delete/open/openOrCreate）与
    `site.grants.*` 空实现、`session-manager.ts`/`account-registry.ts`/`navigation.ts`/IDB `sessions`
    store 整套 v2.1 免密切换路径仍在运行。`docs/PROJECT-STATUS.md` 称引擎「已全部移除，相关目录仅存
    于更早的提交历史中」与事实不符（`git ls-files packages/engine` 仍在 HEAD 且工作区干净）。
11. 文档漂移：根 `package.json` description 仍为「扩展（单账号免密切换）+ 本地引擎（多账号并行在线）」；
    `packages/extension/docs/DESIGN.md` 冻结在 v2.1.0，其 §3「纯扩展无法实现同站多账号并行在线」、
    「DNR 不支持按 tabId 匹配」已被本项目 v2.3+ 的实现推翻；仓库无 README.md 入口。
12. 安全边界：凭证「加密」属设备绑定混淆（PBKDF2 种子与密文同存于扩展本地存储，`credentials.ts`
    自述）；解密后的明文密码在 `chrome.storage.session` 的 pendingAutoLogins 中保留（60s TTL）。
    扩展只保证客户端呈现层隔离，服务端越权属平台缺陷（PROJECT-STATUS §5.1 声明）。
13. 小瑕疵：`parallelSession.statusOf` 的 `enforcementOff` 是同步返回、异步判定，首次渲染可能短暂
    显示健康态（fire-and-forget 的结果被丢弃），靠 3s 轮询自愈。
14. 无自动化单元测试；验证全靠手工操作 + 交互式 E2E 台架。
